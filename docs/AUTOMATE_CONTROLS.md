# Display automation controls

Seven existing displays retain their independent gesture engines. AUTOMATE opens the editor from the top-right of the screen. Green phosphor outline/text becomes a solid mint-green field with dark knockout lettering when a gesture is enabled. Pause/Play sits immediately to its left. Horizontal Soften and Speed rails sit at the bottom; their central labels have a dark backing above the markers, remaining readable at all values. Speed retains logarithmic main-screen travel, 1× snapping, and the existing 0.01–2× range. Both controls retain pointer capture, touch, keyboard and wheel input, synchronised with the editor.

The popup records immediately on press in its drawing area, from the actual pressed position. A new press clears the previous path for that display only. Release finishes the recording and starts looping, including stationary holds. No REC, PLAY or RELEASE controls remain in the popup. Clear Gesture remains above the surface. X assignment appears centered below in yellow; Y appears vertically centered at the left in amber. Direction and End → Start Transition have separate labelled groups. Popup Soften/Speed inputs use the Voice-style physical caps. Click-away and Close both dismiss the editor without stopping playback; pointer-up outside completes recording through capture rather than dismissing it.

No DSP, clock, gesture core, patch format, MIDI or SEQ processing changed. Main screen plotting reserves room for the top and bottom overlay controls. Screen grids still reach the glass edges. Main synth section/control/screen bounds match the previous build.

Validation: Chromium at 1920 and 1280 widths checked all seven display layouts, active/paused styles, visible label backings and tracks, horizontal pointer/keyboard adjustment, popup synchronisation, exact paused position, independent playback, recording, overwrite, stationary hold, Clear, patch recall, audible output and no page errors. Chromium emulated touch checked start/end positions, touch drawing, click-away, horizontal rails and mouse release outside. Screenshots reviewed. Physical tablet/Windows testing was not performed. Historical REC-arm-based browser scripts describe the superseded interface; the focused `automate-controls-browser.cjs` and `automate-touch-browser.cjs` cover this replacement workflow.
